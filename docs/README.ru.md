# Codex Budget: установка и использование

Плагин для Codex Desktop и CLI помогает планировать недельный расход: резерв
20 п.п., выбранный буфер 3 п.п., общий локальный журнал оценок этапов. Это best
effort по инструкциям помощника, не безлимит и не перехват всех запросов.

Нужны Python 3.11+, совместимый штатный Codex CLI (проверяемая базовая версия
0.159.2), вход в Codex и разрешённые пользовательские marketplace plugins.
В CI первого релиза включены macOS, Linux и Windows.

```sh
codex plugin marketplace add trukhinyuri/codex-budget --ref v0.2.0
codex plugin add codex-budget@codex-budget-marketplace
codex plugin list --marketplace codex-budget-marketplace --json
```

Откройте новый чат и вызовите `$codex-budget:codex-budget`; при необходимости перезапустите
Desktop для обнаружения плагина. Он не устанавливает Python, не меняет модель,
auth, платежи, security, hooks или расписания. Для запуска из исходников:

```sh
python3 scripts/budget.py doctor
python3 scripts/budget.py status --fresh
python3 scripts/budget.py assess --task-id CHAT:PHASE --root-id CHAT --estimate-pp 1
python3 scripts/budget.py start --task-id CHAT:PHASE --root-id CHAT --estimate-pp 1
python3 scripts/budget.py finish --task-id CHAT:PHASE
```

В Windows можно использовать `py -3`. В примере 1 п.п. — условная оценка,
не норматив. При неизвестной стоимости опустите estimate: обычный этап получает
defer. Значительный этап требует свежий снимок до 60 секунд; `--short` разрешает
до 12 часов для короткого шага. Приоритет required/urgent сохраняет обязательную
работу с предупреждением; не используйте его ради обхода отсрочки.

Проверка ordinary: U + P + 3 + estimate <=80. Все помощники входят в оценку
этапа. Резервы завершённых этапов остаются unreconciled; не удаляйте их вручную.
При <=35%/опасном темпе откладывается необязательный фон, при <=20% приоритет
остаётся только у обязательной и срочной работы. Другие клиенты могут расходовать
общую квоту. Оценки не являются доказанными верхними границами стоимости.

Данные по умолчанию находятся в `~/.local/share/codex-budget/`, отдельно от кода
плагина. Все клиенты должны использовать одну базу для общего учёта. Параметры
`--state`/`--db` ставятся перед командой; переменные и файл settings подробно
описаны в главном [README](../README.md). Старое наблюдение нельзя датировать как
новое. Неподдержанное серверное окно и ошибки чтения остаются неизвестными.

`horizon` показывает наблюдённый общий расход за скользящие 7 и 30 дней,
покрытие наблюдениями и прогноз спроса. Интервалы через reset, смену аккаунта
и аномалии не дают новой доступной квоты. Будущая ёмкость остаётся неизвестной;
месячный прогноз не является месячным лимитом или гарантией непрерывной работы.

`advise` рекомендует модель, effort и минимальную ширину команды по сложности,
неопределённости и цене ошибки. Явный выбор пользователя, включая Ultra,
сохраняется. Для проверки поддержки передайте свежий полный JSON `model/list`
через `--catalog`; чтение каталога само по себе не подтверждает effective settings.
Рекомендация применяется только штатным интерфейсом перед новым ходом.
Утилита не меняет текущий ход, config defaults или скорость.

`amend --task-id ... --estimate-pp ... --reason ... --evidence ...` позволяет
обоснованно дополнить неизвестную оценку положительным числом или увеличить
известную. Помощник должен проверить источник; утилита сохраняет текст и аудит,
но не подтверждает его истинность. Уменьшить/удалить резерв или списать фактическую
стоимость нельзя. Завершённый этап остаётся unreconciled. Повторно проверьте
допуск через assess/start; сама amendment не разрешает новый запуск. При установке
существующие оценки не изменяются.

Работоспособность проверяется тестами, CI, штатной установкой и реальным чтением
квоты в указанных условиях. Абсолютная гарантия доступности сервера и сохранения
резерва невозможна. См. [контракт качества](QUALITY.md) и ограничения в README.
